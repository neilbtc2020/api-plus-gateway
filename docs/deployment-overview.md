# 部署概览

API Plus Gateway 的完整部署通常由网关服务、前端控制台、数据库、Redis、支付回调和模型供应商渠道组成。展示仓库不提供完整源码和生产配置，本文档用于说明上线前需要准备的关键项。

## 推荐组件

| 组件 | 用途 |
| --- | --- |
| API Plus 服务 | 网关、后台 API、计费、路由和任务处理 |
| Web 控制台 | 用户侧和管理员侧页面 |
| PostgreSQL/MySQL | 生产数据库 |
| Redis | 缓存、渠道亲和、额度缓存、多机协同 |
| 反向代理 | HTTPS、域名、静态资源、回调入口 |
| 支付渠道 | Stripe、易支付或其他可扩展支付方式 |
| 模型供应商 | OpenAI-compatible、Claude、Gemini、Rerank 等 |

## 生产配置重点

1. 设置强随机 `SESSION_SECRET`，多机部署必须保持一致。
2. 使用 Redis 时设置稳定的加密密钥，避免缓存数据无法解密。
3. 数据库账号、Redis、后台管理员密码和支付密钥不要使用默认值。
4. 支付回调域名必须走 HTTPS，并在支付平台配置正确的 notify/return 地址。
5. 渠道密钥要按供应商、模型、分组隔离，避免一个 key 泄露影响全部业务。
6. 日志中避免输出完整用户 token、供应商 key、支付密钥和 OAuth secret。
7. 上线前用小额支付完成真实闭环验证，包括支付成功、回调、额度到账、退款或异常订单处理。

## 上线检查清单

| 检查项 | 目标 |
| --- | --- |
| 域名与 HTTPS | 用户、API、支付回调均可通过 HTTPS 访问 |
| 数据库备份 | 支持定时备份和恢复演练 |
| Redis 可用性 | 缓存、限流、亲和等功能在重启后表现可控 |
| 支付闭环 | 真实支付、回调验签、到账、对账全部验证 |
| 模型路由 | 常用模型、备用渠道、失败重试和价格倍率已确认 |
| 管理后台 | Root/管理员账号、权限和高危设置入口已加固 |
| 监控告警 | 服务健康、错误率、支付异常、余额异常可被发现 |

## 常见部署形态

| 形态 | 适用场景 |
| --- | --- |
| 单机 Docker Compose | 小规模验证、演示、早期运营 |
| 单机服务 + 云数据库 | 降低数据库维护成本，适合轻量生产 |
| 多实例 + Redis + 托管数据库 | 面向更高并发和更稳定的生产环境 |
| 私有化部署 | 企业内部网关、私有模型、合规要求更高的场景 |

## 不建议跳过的验证

上线前至少完成一次完整链路测试：

1. 新用户注册或 OAuth 登录。
2. 创建用户令牌。
3. 完成充值或订阅支付。
4. 调用一个低成本模型。
5. 检查额度扣减、账单记录、渠道日志和错误日志。
6. 手动模拟渠道失败，确认备用渠道或错误反馈符合预期。
